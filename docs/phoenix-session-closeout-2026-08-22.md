## Runtime defects found and corrected during physical validation

### Native bed mesh command

Physical testing exposed stale `BED_MESH_CALIBRATE_BASE` calls in `phoenix-debug.cfg` and `phoenix-print-start-end.cfg`. They were replaced with native Klipper Mainline calls:

```gcode
BED_MESH_CALIBRATE METHOD=rapid_scan
BED_MESH_CALIBRATE METHOD=rapid_scan ADAPTIVE=1 ADAPTIVE_MARGIN=10
```

This removed the final runtime-invalid wrapper name from Phoenix bed-mesh execution.

### Cooldown fan

`PHOENIX_MACHINE_LEVEL` and `PHOENIX_REFERENCE_BED_MESH` were updated to use full part-fan cooling during the wait for nozzle temperature <= 50 C:

```gcode
M106 S255
TEMPERATURE_WAIT SENSOR=extruder MAXIMUM=50
M107
```

### READY_UP cleaner temperature

`PHOENIX_CLEAN_NOZZLE` now accepts a `TEMP` parameter while retaining 170 C as standalone default. `PHOENIX_READY_UP` passes its requested nozzle temperature to the cleaner, so a request such as `NOZZLE=160` no longer heats to 170 C first.

## OrcaSlicer residue discovered

The integrated print test exposed repeated:

```text
Unknown command:"_DEMON_ADAPTIVE_PA"
```

Investigation proved that these calls were embedded in an older G-code generated by OrcaSlicer through:

```text
change_extrusion_role_gcode = _DEMON_ADAPTIVE_PA TYPE=[extrusion_role]
```

This is not a Phoenix runtime dependency. It is a stale slicer-profile setting and must be removed from the Phoenix Orca profile. A temporary copy of the test G-code was generated with the executable `_DEMON_ADAPTIVE_PA` lines removed.

## First-layer observation

The 5-zone first-layer print completed, but the photographs show non-uniform surface quality between zones despite correct QGL and a successful adaptive mesh. This is now a separate print-quality/bed-compensation investigation and is intentionally not treated as a Phoenix macro failure.
